Your profile lives in the dashboard settings. Everything on this page is an account-security surface: it requires an interactive session, so API keys and connected apps cannot change your name or picture.

## Display name

The display name is optional at registration and editable afterward. Set it, change it, or clear it from settings, or via the API:

<CodeGroup>

```bash curl
curl -X PATCH "https://spoo.me/auth/me" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_JWT" \
  -d '{"user_name": "Jane Doe"}'
```

```python Python
import requests

response = requests.patch(
    "https://spoo.me/auth/me",
    json={"user_name": "Jane Doe"},  # or None to clear it
    headers={"Authorization": "Bearer YOUR_JWT"},
)
print(response.json()["user"])
```

</CodeGroup>

Send a string to set the name (1 to 255 characters) or an explicit `null` to clear it. The endpoint is JWT-only; an API key gets a `403`.

## Profile picture

Your picture can come from a linked sign-in provider or a custom upload. All three operations live under `/api/v1/me/profile-pictures` and require a signed-in session:

| Action | Endpoint |
| --- | --- |
| List available pictures | `GET /api/v1/me/profile-pictures` |
| Use a provider picture | `POST /api/v1/me/profile-pictures` with a `picture_id` from the list |
| Upload a custom picture | `POST /api/v1/me/profile-pictures/upload` |
| Remove the picture | `DELETE /api/v1/me/profile-pictures` |

<Steps>
  <Step title="Upload a picture">
    Send the image as a base64 data URI. PNG, JPEG, and WebP are accepted, up to 512 KB:

    ```bash
    curl -X POST "https://spoo.me/api/v1/me/profile-pictures/upload" \
      -H "Content-Type: application/json" \
      -H "Authorization: Bearer YOUR_JWT" \
      -d '{"image": "data:image/png;base64,iVBORw0KGgo..."}'
    ```
  </Step>
  <Step title="Or pick a provider picture">
    `GET /api/v1/me/profile-pictures` returns one entry per linked OAuth provider, with `is_current` marking the active one. Post its `picture_id` back to switch.
  </Step>
  <Step title="Remove it anytime">
    `DELETE /api/v1/me/profile-pictures` falls back to the default avatar. The call is idempotent.
  </Step>
</Steps>

## Email verification

Verifying your email is what unlocks creating things on your account. Until it is done, requests that create resources, including shortening links while signed in, creating API keys, and registering custom domains, are rejected with `403` and code `EMAIL_NOT_VERIFIED`.

The gate exists because everything you create is attributed to your account. An unverified address means an unreachable owner, which matters the moment a link needs an abuse follow-up or an account recovery.

<Steps>
  <Step title="Get the code">
    A 6-digit code is emailed to you at sign-up. To re-send it, use the prompt in the dashboard or `POST /auth/send-verification`. Sending a new code invalidates any previous unused one.
  </Step>
  <Step title="Enter the code">
    Submit it in the dashboard or via `POST /auth/verify-email` with `{"code": "123456"}`. Codes expire, and expired or already-used codes are rejected.
  </Step>
  <Step title="You're verified">
    Your session is refreshed with the verified status; no need to sign out and back in.
  </Step>
</Steps>

<Note>
  Re-sends are limited to 1 per minute and 3 per hour. If the email does not arrive, check spam before requesting another; each re-send invalidates the previous code.
</Note>
